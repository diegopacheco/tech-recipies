The verbs and status codes remain familiar. What changes is how requests become frames, share a connection, recover from loss, compress headers, and reach the origin.

04 / Tradeoffs

Faster is still contextual.

Network quality, proxy support, CPU cost, tooling, and fallback behavior determine which version wins for a particular request path.

HTTP/1.1

Pros
  • Readable on the wire
  • Universal infrastructure support
  • Simple operational model
Cons
  • No multiplexing
  • Repeated headers
  • More connections for concurrency

HTTP/2

Pros
  • Efficient multiplexing
  • HPACK header compression
  • Mature client and proxy support
Cons
  • TCP-wide loss blocking
  • More complex inspection
  • One hot connection can concentrate risk

HTTP/3

Pros
  • Independent loss recovery
  • Fast secure setup
  • Connection migration
Cons
  • UDP may be blocked
  • Higher user-space CPU cost
  • TCP fallback remains necessary
