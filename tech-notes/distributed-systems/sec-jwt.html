Security sequence 01

How JWT works

A JSON Web Token is a signed credential. The client obtains it once, sends it with later requests, and the API verifies it without asking the authentication server about every request.

01

The client proves identity

The client sends credentials over TLS. This may be a password, passkey, authorization code, or another accepted proof.

Authentication
Rule 01

Signed is not encrypted

Anyone holding a JWT can decode its header and payload. Never put secrets or sensitive personal data in its claims.

Rule 02

Claims still need checks

A correct signature is only one gate. The API must also validate issuer, audience, expiration, and required permissions.

Rule 03

Keep access short-lived

Short expiration limits exposure after theft. Use a controlled refresh flow when sessions need to last longer than an access token.
