Why it happens

A lazy association is a placeholder. Fetching the parent does not fetch the children. The first call to author.getBooks() initializes that author's collection with a new SQL query.

The loop hides the cost because the Java code looks like ordinary object traversal while database traffic multiplies behind it.

  1. 1Hibernate loads every Author with one query.
  2. 2Each books collection remains lazy and uninitialized.
  3. 3Touching each collection triggers one query per author.
  4. 4100 authors become 101 database round trips.

Spring Boot 4.1.0

Does repository.findAll() create N+1?

It can, but not always

findAll() normally starts with one query for the root entities. N+1 depends on the entity mappings, fetch plan, and which relationships are used. Spring Boot 4.1.0 does not automatically remove this risk.

Lazy relationship

The repository call can finish with one query. A later loop, mapper, or JSON serializer that touches the relationship can trigger one additional query per entity.

Eager relationship

Hibernate must initialize it. Depending on the query and fetch mapping, it may use joins or secondary selects, so N+1 can occur while findAll() runs.

Repository fetch planExplicit
public interface AuthorRepository
    extends JpaRepository<Author, Long> {

  @Override
  @EntityGraph(attributePaths = "books")
  List<Author> findAll();
}
Spring Boot 4.1 reference Spring Data EntityGraph Hibernate fetch modes

Choose the fetch plan intentionally.

The best option depends on the use case. Fetch only the relationships the current operation actually needs.

01 / DIRECT

JOIN FETCH

Load the parent and required relationship in the same query. Clear and effective for a known access path.

02 / DECLARATIVE

EntityGraph

Describe which attributes should be loaded without embedding a fetch join in the query text.

03 / BATCHED

Batch fetching

Use @BatchSize or hibernate.default_batch_fetch_size to load multiple lazy collections per query.

If code iterates over entities and touches a lazy relationship, inspect the SQL. The useful unit is not “objects loaded”; it is database round trips.
