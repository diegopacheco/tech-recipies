      Which one should I pick?

      There is no single winner — match the tool to whether you need fan-out, replay, routing, transactional enqueue, or just decoupling with retry.

      → On AWS, decouple with zero ops: SQS. Visibility timeout + DLQ give you retry for free.

      → One event, many independent reactions: SNS — usually SNS → SQS so each subscriber gets a durable buffer.

      → High-throughput streaming, event sourcing, replay: Kafka — the retained log lets many consumer groups rewind.

      → Sub-ms job queue, Redis already in the stack: Redis Streams — accept a small window of loss on crash.

      → Complex routing, priorities, per-message retry, RPC: RabbitMQ.

      → Enqueue must be atomic with a DB write, modest volume: Postgres (transactional outbox).

      Three pros and three cons each

      The honest tradeoffs. Every one of these is the right answer for something and the wrong answer for something else.

      SQS decouples with built-in retry; SNS fans one event out to many; Kafka is a replayable log; Redis is fast but volatile; RabbitMQ routes with precise per-message control; Postgres makes the enqueue atomic with your data. See the notes.
