Concurrency threshold 01

C10K

The challenge of keeping 10,000 client connections open without losing the server to thread stacks, context switches, blocking calls, or unbounded queues.

10,000 concurrent connections, not requests per second

The problem

Idle clients should not consume active threads.

A blocking server commonly assigns one thread or process to each connection. At 10,000 connections, thread memory, scheduler overhead, lock contention, file descriptors, and kernel socket state become a capacity wall.

C10K concerns concurrent connections. Many may be idle or send data infrequently, but the server must remain responsive when any of them becomes active.

Pressure points

Where the blocking model breaks

Thread memory

Each thread carries a stack and runtime metadata even while its connection waits.

Context switching

The scheduler moves between thousands of threads and repeatedly displaces useful CPU-cache data.

Blocking work

A slow client, database, DNS lookup, or file operation holds a thread without useful progress.

Kernel state

Every socket consumes a descriptor, TCP structures, and send and receive buffer capacity.

Shared locks

Queues, allocators, and shared application state turn into synchronization bottlenecks.

Connection churn

Handshakes and disconnect storms add accept, allocation, cleanup, and TLS work.

The scalable model

React only when a socket can make progress.

The operating system reports ready sockets through `epoll`, `kqueue`, IOCP, or `io_uring`. A small event-loop pool processes those sockets and moves on immediately when a read or write would block.

  • Non-blocking sockets prevent idle clients from occupying threads.
  • Compact state machines preserve protocol progress per connection.
  • Bounded worker pools isolate CPU-heavy or unavoidable blocking work.
  • Bounded buffers stop slow readers from consuming unlimited memory.
  • Backpressure protects the event loop and downstream services.

Count every layer

Application state, parser state, input and output buffers, TLS state, kernel socket structures, and TCP buffers all contribute to the real connection cost.

Tune the whole host

File-descriptor limits, accept queues, TCP memory, idle timeouts, firewalls, load balancers, and outbound port capacity must agree with the target.

Validation

Opening sockets is only the first checkpoint.

  • Hold at least 10,000 real connections.
  • Measure p50, p95, p99, and maximum latency.
  • Track CPU, context switches, memory, descriptors, and event-loop delay.
  • Mix idle clients, active clients, slow readers, and slow writers.
  • Exercise connection storms, abrupt disconnects, and slow dependencies.
  • Verify recovery after the load returns to normal.
