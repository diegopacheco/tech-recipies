The core loop

One transaction. Four transformations.

The network replaces a central bookkeeper with shared rules, cryptography, and synchronized copies of the ledger.

01

Sign

A wallet authorizes a transaction with a private key. The signature proves permission without revealing the key.

02

Broadcast

The signed transaction travels peer to peer. Multiple nodes receive the same proposed change.

03

Validate

Nodes independently check signatures, balances, formatting, and protocol rules before accepting it.

04

Commit

A consensus process selects a block. Each node appends it and the transaction gains confirmations.

Why the ledger holds together

Four reinforcing properties

#
Hash linking

Each block fingerprints its content and points backward, exposing any altered history.

K
Digital signatures

Only the holder of a private key can authorize spending from its associated address.

N
Replication

Many nodes retain the ledger, removing dependence on one database or operator.

✓
Consensus rules

Nodes accept only valid blocks and converge on a canonical transaction order.
